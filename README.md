# JFCRAFT 2.0 — development preview

Лаунчер сборок Minecraft на Python/Tkinter. Окно установки, проверки и запуска;
отдельные профили, сохранение настроек, Java на профиль и журнал ошибок.

## Запуск

Python 3.11 x64 с Tkinter:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Данные: `%APPDATA%/JFCRAFT`. Для тестового или переносного каталога задайте
`JFCRAFT_HOME`. Старые `.minecraft` и `.jfcraft-*` автоматически не изменяются.
Vanilla Expanded, Pokecraft, New IC, Winter Craft и Middle-earth Chronicles Classic доступны в библиотеке. Их файлы привязаны
к историческому коммиту, а не к изменяемой ветке. Первичная установка требует сети.
Нужна Java 17 x64; для LOTR 1.7.10 — Java 8 x64. Можно выбрать `java.exe` в окне.

Авторизация сейчас локальная по нику. Вход Microsoft и доступ к серверам,
требующим лицензионную сессию, пока не реализованы.

## Обновления сборок

При установке/обновлении библиотека загружается из `packs/catalog/index.json` на GitHub,
затем проверяется `update_url` выбранной сборки. Новое описание сохраняется
локально; сами файлы выпуска должны находиться по неизменяемым ссылкам.
При недоступности канала показывается сообщение и используется сохранённое
описание. Некорректный манифест или чужой ID прекращают операцию.

«Играть» сначала устанавливает отсутствующую сборку, затем запускает игру. Для уже
установленной сборки она запускает сохранённый установленный
выпуск без сетевых запросов лаунчера, проверки хешей и установки Minecraft/Forge.
Сами моды и Minecraft могут обращаться к сети. Для проверки файлов или обновления
выберите «Обновить / восстановить» в меню «⋯». Новая установка требует интернета.
Удаление находится в том же меню и требует подтверждения. Установленные файлы,
включая миры, переносятся в `%APPDATA%/JFCRAFT/removed-packs` для восстановления;
это не освобождает место на диске. Обновление / восстановление не затрагивает `saves`.

После проверки SHA-256 скачиваются только отсутствующие/изменившиеся файлы.
Загрузки идут во временный каталог. Изменения применяются после проверки всех
загрузок; предыдущие файлы остаются в `.jfcraft-backups`. Журнал транзакции
позволяет восстановить предыдущий набор после прерывания установки.

Политики файлов:

- `managed`: обновляется точно по выпуску; устаревший управляемый файл убирается
  с резервной копией. Все файлы в `mods`, отсутствующие в манифесте, также убираются
  в резервную копию, включая файлы во вложенных папках версий. Перед обычным запуском
  этот список проверяется локально по установленному манифесту, без сети и хеширования.
- `merge`: конфиг обновляется, только если пользователь не менял прежнюю копию.
  Изменённый конфиг сохраняется, о нём сообщается в журнале. Это не построчное слияние.
- `preserve`: начальные `options.txt`/`servers.dat` устанавливаются только при отсутствии.

Миры не входят в разрешённые пути манифеста. Установка архивных сборок проверяет
как сам ZIP/RAR, так и каждый извлечённый файл. RAR читается через системный
`tar.exe` Windows 10/11; WinRAR не требуется. Извлекаются только явно перечисленные
файлы; полная распаковка архива не используется.

## Выпуск новой LOTR-сборки

Подтверждённая основа прежней Middle-earth Chronicles: Minecraft 1.7.10,
Forge `1.7.10-10.13.4.1614-1.7.10`, Java 8. Новый список модов ещё готовится.
Новая сборка должна иметь отдельный ID; обновления одной сборки сохраняют ID.

```powershell
python tools/build_pack.py "D:/Packs/LOTR-New" "output/lotr-1.0.0" --id middle-earth-new --name "Middle-earth Chronicles" --version 1.0.0 --minecraft 1.7.10 --forge 1.7.10-10.13.4.1614-1.7.10 --installed-version 1.7.10-Forge10.13.4.1614-1.7.10 --java 8
```

Генератор не включает сохранения, логи, аккаунты или сам Minecraft. Конфиги по
умолчанию получают `merge`; обязательные изменения конфига можно пометить
`managed` в манифесте перед выпуском.

1. Проверить подготовленную сборку на новом тестовом мире.
2. Загрузить файлы из выходного каталога в GitHub Release с тегом
   `middle-earth-new-1.0.0`. Не заменять файлы опубликованного выпуска.
3. Разместить копию `manifest.json` в `packs/middle-earth-new.json` ветки `main`.
4. Добавить ID сборки в `packs/catalog/index.json`. Библиотека игроков обновляется
   автоматически при установке/обновлении; ручное подключение манифестов не требуется.

Встроенные описания и локальный кеш сохраняют библиотеку доступной без сети.
`manifest_revision` защищает исправленную редакцию того же выпуска от замены
устаревшим описанием с сервера. SHA-256 считается по исходным байтам Git без
Windows-преобразования переносов строк; аудит: `python tools/audit_catalog.py`.

Первые три архивных описания воспроизводятся `python tools/build_legacy_catalog.py`.
Winter Craft и классическая LOTR — `python tools/build_additional_catalog.py <копия-репозитория>`
из закреплённого в скрипте коммита. Состав модов этих сборок берётся из `mod_list.txt`;
дополнительно включаются вложенные библиотеки Forge. Старые неактивные JAR не устанавливаются.
Исходные архивы и моды в `download-files` сохранены.

## Проверки и Windows EXE

```powershell
python -m unittest discover -s tests -v
python -m pip install "pyinstaller>=6,<7"
python -m PyInstaller --clean --noconfirm jfcraft.spec
```

Результат: `dist/JFCRAFT.exe`. Для сборки нужен рабочий Tkinter/Tcl.
Запуск двух окон для одного профиля блокируется на время установки и игры.
Отмена проверяется между сетевыми порциями файлов и этапами установки Forge;
уже запущенную игру кнопка отмены не завершает.

Автообновление **самого EXE** не реализовано: старый небезопасный механизм,
удалявший папку перед загрузкой, больше не вызывается. Обновления сборок
и обновления приложения — независимые процессы.
